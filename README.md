# NihongoQuest

현재 구조와 과거 작업 기록은 [문서 목차](docs/README.md)에서 확인할 수 있습니다.

일본어 학습 및 퀴즈 게임 애플리케이션 'NihongoQuest'의 소스 코드 저장소입니다.

## 일본 뉴스 API 설정

1. [The News API](https://www.thenewsapi.com/)에서 무료 API 토큰을 발급합니다.
2. `.env.example`을 참고해 `.env`에 아래 값을 추가합니다.

```env
THE_NEWS_API_TOKEN="발급받은_토큰"
```

환경변수를 추가하거나 변경한 뒤에는 개발 서버를 다시 실행해야 합니다. 토큰이 없거나 외부 API 호출에 실패하면 NHK RSS, 내장 뉴스 순서로 자동 전환됩니다.

뉴스는 한국 날짜 기준의 일일 풀을 확인하고, 갱신이 필요하면 최대 40페이지를 조회해 중복을 제거한 기사 100건을 PostgreSQL에 저장합니다. 화면에는 무작위 10건을 표시합니다. 일반 응답은 서버 메모리에 15분간 캐시합니다.

다시 뽑기는 응답 캐시를 건너뛰고 자료를 다시 선택합니다. 당일 풀이 준비되어 있으면 기사 수집을 반복하지 않지만, 풀이 없거나 갱신이 필요하면 외부 수집을 시도할 수 있습니다. 수집 실패 시 기존 저장 자료를 활용하고, 사용할 자료가 부족하면 NHK RSS·내장 자료 순으로 전환합니다.

초보스타터의 일상회화는 뉴스 API나 Quiz DB를 사용하지 않습니다. 소스에 있는 100개 중 화면 진입 시 중복 없는 5개를 추첨하며, ↻ 버튼으로 다시 뽑을 수 있습니다.

## 문제 데이터 가져오기

메인 화면의 문제 동기화 버튼은 제거했습니다. 현재 문제는 DB에서 바로 출제하며, 문제를 가져오거나 복구할 때만 아래 관리 명령을 사용합니다. 일반 가져오기는 사용자·포인트·풀이 기록·오답노트·단어장을 삭제하지 않습니다.

현재 N1·초보·모의고사 문제를 함께 동기화하려면 다음 명령을 사용합니다. `.env`의 PostgreSQL에 연결하며, 스테이지가 없으면 생성합니다.

```bash
npm run db:seed
```

2026-10-20 코드로 집계한 가져오기 카탈로그는 N1 연습·워들 1,184개, 초보 492개, 모의고사 별도 ID 20개로 총 1,696개입니다. 이는 현재 DB의 실시간 활성 문항 수가 아닙니다. 초보는 문자 입문 92문항과 네 아레나 각각 100문항입니다.

분류된 기존 문제의 DB 수정 내용과 상태는 기본 가져오기가 덮어쓰지 않습니다. 없는 문항은 생성하고, 카탈로그 ID와 일치하는 미분류 LEGACY 문제는 갱신할 수 있습니다. 일반 가져오기는 과거 문제 행을 삭제하지 않습니다. 코드 자료로 카탈로그 문항의 내용·상태를 강제 복원할 때만 `npm run db:seed -- --overwrite`를 사용합니다.

`POST /api/seed`도 같은 기본 가져오기를 수행합니다. 운영 환경에서는 `SEED_ADMIN_TOKEN`의 Bearer 인증이 필요하고, 개발 환경에서는 토큰 검사 없이 허용됩니다. GET 요청은 거절합니다.

모든 아레나와 모의고사는 **DB의 활성 문제를 조회해 출제·채점**합니다. 코드 데이터는 초기 가져오기와 복구용이며 풀이 중 DB에 덮어쓰지 않습니다. `jlptLevel`, `arenaCategory`, `status`와 유형별 메타데이터로 출제 대상을 관리합니다. DB 스키마 적용은 `npm run db:push`를 사용합니다. [현재 아레나 구조](docs/arena-architecture.md)를 참고하세요.

과거 교체·추가·검수 기록은 [문서 목차의 보관 기록](docs/README.md#과거-작업과-검수-기록)을 참고하세요. 해당 시점의 DB 집계와 작업 기록은 현재 운영 명령과 구분합니다.

초보 문제만 직접 동기화하려면 다음 명령을 사용합니다.

~~~bash
npm run db:seed:beginner
~~~

## 앱 설치(PWA)

Chrome·Edge 등의 설치 가능한 환경에서는 메인 화면의 앱 설치 아이콘을 사용할 수 있습니다. iPhone과 iPad에서는 Safari 공유 메뉴의 **홈 화면에 추가**를 선택합니다.

서비스 워커 설치 기능은 localhost 또는 HTTPS 환경에서 동작합니다. 네트워크가 끊기면 전용 오프라인 안내 화면을 표시하며, API 기반 문제 풀이와 데이터 저장에는 인터넷 연결이 필요합니다.
